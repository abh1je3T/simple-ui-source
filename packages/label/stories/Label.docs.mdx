<Subtitle>A typographic element for associating text with form controls.</Subtitle>

<Description>
  The `Label` component provides a clear, accessible way to attach a text description to an input element. It manages font sizes, weights, and handles the display of required indicators automatically.
</Description>

<Primary />

## Key Features

- **Required Indicator**: Automatically appends an accessible asterisk (`*`) when the `required` prop is true.
- **Scalable Sizes**: Available in `sm`, `md`, and `lg` to match the sizing of associated form controls.
- **Weight Control**: Adjustable font weights (`regular`, `medium`, `semibold`, `bold`) for visual emphasis.
- **Native Accessibility**: Uses the native `<label>` element, which expands the hit area for controls like checkboxes and radios.

---

## Usage Guidelines

### Do:
- **Pair with Controls**: Always associate a `Label` with a form input, either by wrapping the input or using the `htmlFor` prop.
- **Be Concise**: Keep label text short and direct (e.g., "Email Address" rather than "Please enter your email address here").
- **Match Sizes**: Ensure the `size` of the label matches the `size` of the associated input for visual harmony.

### Don't:
- **Use as Headings**: Do not use `Label` components to create section headings; use the `Heading` component instead.
- **Hide Labels**: Avoid hiding labels completely. If a design requires no visible label, ensure you provide an `aria-label` directly on the input.

---

## Usage Pattern

```tsx
import { Label } from "@simple-ui/label";
import { Input } from "@simple-ui/input";

const Example = () => {
  return (
    <div style={{ display: 'flex', flexDirection: 'column', gap: '8px' }}>
      <Label htmlFor="email-input" required weight="semibold">
        Email Address
      </Label>
      <Input id="email-input" type="email" placeholder="name@example.com" />
    </div>
  );
};
```

---

## Best Practices

> [!TIP]
> **Wrapping vs htmlFor**: Wrapping an input (like a `Radio` or `Checkbox`) directly inside a `Label` automatically associates them without needing an `id` or `htmlFor`. However, for text inputs, using `htmlFor` is generally preferred for layout flexibility.

> [!IMPORTANT]
> **Required Fields**: While the `required` prop visually indicates the field is mandatory, ensure the actual `<input>` also has the native `required` attribute for HTML5 validation and screen readers.

## Accessibility Audit

- **Click Target**: Clicking the label text automatically focuses the associated input or toggles the associated checkbox/radio button.
- **Semantic HTML**: Uses the native `<label>` tag.
- **Required Asterisk**: The asterisk generated by the `required` prop is often styled via CSS. Ensure that screen readers are aware of the required state by adding `aria-required="true"` or `required` to the input element itself.
